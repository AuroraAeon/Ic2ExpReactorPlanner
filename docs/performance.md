# 模拟性能报告

基线为上游 `5b4cee96a71cc4c8367fff398bf4f9752aff69cc`。Windows 11、Intel Core Ultra 9 275HX、Microsoft OpenJDK 21.0.7、`-Xms256m -Xmx768m`，基线和现版本均以 Java 17 目标构建。

## 旧版布局前后对照

同一 [基准程序](../benchmark/Ic2ExpReactorPlanner/SimulatorBenchmark.java) 对每个用例预热 8 次，采集 12 个各含 3 次模拟的样本，报告每次模拟的中位数。计时包括布局创建和模拟，关闭 CSV 与界面绘制。内存指标来自 JVM 线程分配计数器，表示执行模拟的线程累计分配字节。表中吞吐量是反应堆更新数除以墙钟时间。

- **稀疏铀堆**由一根单联铀棒和一个散热片构成。4.791 → 4.120 ms，4,174,688 → 4,854,631 更新/秒，1,183,789 → 30,064 B/次。
- **满格 EU** 同时布置铀棒和高级散热片。18.679 → 16.857 ms，1,070,851 → 1,186,561 更新/秒，9,830,195 → 204,520 B/次。
- **流体与热交换** 为 MOX、热交换器和散热片混排。14.494 → 11.610 ms，690,033 → 861,429 更新/秒，16,112,661 → 157,237 B/次。
- **自动化钍堆** 布置交错的四联钍棒和 360k 氦冷却单元，运行 30,000 次更新。39.587 → 20.598 ms，757,833 → 1,456,453 更新/秒，14,599,728 → 172,573 B/次。

四组旧版用例的总更新数、EU、HU、堆温上下界和首个耗尽或失效事件在前后测量中一致。GTNH 2.9.0 有意改动了启用此配置时的物理规则，因此前后性能比较固定为旧版物理。测试用例吞吐提高约 11%–92%，每次分配下降约 97%–99%。墙钟性能因 JVM、CPU 和系统负载变化。

初始布局只收集一次非空格和燃料棒，关闭自动换件或冷凝器注入时跳过其检查。热路径中的邻接列表替换为局部引用或固定缓冲区，保留游戏要求的访问顺序。频繁更换元件时保留计数并限制逐次文字日志。每次更新的网格状态依赖上一轮以及当前行内已经更新的元件，热量和脉冲按槽序运算。缓存最终结果会把布局、初始温度、版本、冷冻机参数、脉冲和更新上限全部纳入键，本次未引入这种结果缓存。

## 独立布局的并发

使用同一批 16 个完整 GTNH 用例，每批包含 8 份被动钍布局与 8 份真空冷却布局，分别测试 1、2 和 4 个固定工作线程。预热 4 批，测量 8 批。

- 1 线程中位数 1,319.551 ms/批，12.13 布局/秒。
- 2 线程中位数 837.284 ms/批，19.11 布局/秒。
- 4 线程中位数 442.542 ms/批，36.15 布局/秒。

每批逐个比对更新数、EU、最大堆温、失效时间、燃料产物和真空换件统计。三个线程配置的记录均相同。程序暴露可并行调用的独立布局模拟入口。桌面界面同一工作区保留一个正式运行结果任务，使用后台线程实现取消与进度。
